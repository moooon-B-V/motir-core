Motir AI callout — the Debug with Motir AI row

MOTIR-7045 · story MOTIR-7042. The orb's callout gains a third row, Debug with Motir AI. Like the two rows above it, it opens the one Motir AI surface at the same href. Unlike the report widget's offer, it sends nothing. It puts a short template in the composer and waits for the person to describe the bug.

Delta on ai-callout-menu.mock.html panels 3–4 (the menu and the row anatomy). The orb, the popover, its header, its keyboard model and the two shipped rows are unchanged and are reproduced only so the new row has its context.

One registry entry, one glyph mapping, two message keys. The row is a third object in aiCalloutActions(href): { id: 'debug', icon: 'bug', titleKey: 'aiCallout.actions.debug.title', descriptionKey: 'aiCallout.actions.debug.description', href }. It has the same href as the other two rows. AiCalloutIcon gains 'bug', and AiCalloutMenu's ICONS record maps it to lucide Bug. The record is exhaustive, so the type will not compile without the mapping.

Position 3, ordinary tile. Only position 1 wears the filled hero tile. This row takes the accent-tint tile (--el-accent 11% over --el-page-bg, glyph --el-accent-on-surface), as “Ask about this project” does. The registry comment reserved position 3 for “Help with a task” (wrench), which has not landed. When it does, it takes position 4.

No gate of its own. The orb is mounted only when showPlanWithAi holds: Motir AI configured, an active project, and ai:plan. That is exactly the set of people who may send a debug turn, so the row needs no per-row check. It never appears dimmed. When the gate fails, the orb is not rendered at all, and neither is its menu.

Message key shell.aiCallout.actions.debug.prefill. The two lines are separated by one newline, and each line ends in a colon followed by a single space. The field takes focus with the caret at the end of the first line, so the person types what happens and then arrows down. The shipped multi-line composer (MOTIR-6236) grows to fit the two lines.

Why a template and not a starter chip. The ask row seeds nothing and grew the starter set instead. That works for a question, which the person can type from scratch. A bug report has a shape, and the widget already asks for it: “Steps, expected vs. actual”. The two lines are that shape. Once filled in, they are what the classifier reads as debug (A1.1: a turn that reports broken behaviour).

Nothing is sent (§5, A1.3). This row uses the shipped initialDraft seam, the refusal re-plan's “pre-fill and wait” (MOTIR-6210). The seed is the draft's initial value and nothing more. The person may edit it or clear it, and while it is in the field the starter chips stay hidden. No intent crosses the wire. It is not autoSendTurn, because these words are Motir's, not the person's.

The thread and its chrome are unchanged. The rail opens on the project conversation with its shipped opener and mode pill. It shows no item header, no debug mode and no intent control.

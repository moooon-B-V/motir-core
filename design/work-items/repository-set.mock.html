The repository SET on the work-item detail page

MOTIR-2725 · MOTIR-2413. A work item records an ORDERED SET of repositories; its first element is the PRIMARY that a dispatch routes to, and the item is not complete until every repository on the list has a pull request merged onto that repository's own default branch. The rail answers where does this ship, and has it?; the shipped Development section answers which pull request? — and gains one row it never had, for a repository that has none. Rail measured at the shipped 18rem (app/(authed)/items/[key]/page.tsx).

0THE DOOR — where the field sits in the shipped rail.

The field has no button and no menu item: its access path IS its position, so that is the thing to draw. It lands after Estimate and before the collapsed Provenance disclosure — last of the always-visible fields. Reasoning: it is read at DISPATCH and REVIEW time, not at triage time, so it must not push Status, Assignee or Priority down the rail; but it is more actionable than provenance (it gates completion), so it stays expanded rather than joining that disclosure. Neighbours dimmed; the shipped order is CoreFieldsPanel.tsx's.

2bA merge whose branch Motir never recorded — the third state, and it HOLDS.

So the repository is neither delivered nor outstanding — it is unknown, it holds the card, and the surface says which question a person has to answer. This state is finite and shrinking: every merge from now on records its branch.

Delivered — merged onto that repository's own default branch; the only state that satisfies the gate. Awaiting — no such merge; open or merge the pull request. Unknown branch — a merge Motir has, on a branch it does not; say which branch it landed on. Not created — the row is proposed or creating; the repository does not exist, so the next action is the project's establish step and NOT GitHub. Skipped — the row was declined, so the project is deliberately code-less there; it is the ONE state that does not hold the card, and it is drawn quiet for exactly that reason.

2dTHE DESTINATION — what the reader lands on when they follow a repository.

DRAW THE ENTRANCE, not just the affordance. Following a repository goes to that repository's row on the project's own settings page (/settings/project/repositories, anchored on the row) — not out to the host. Two reasons, and the second one decides it: the card points at a project_repository ROW, so the row is what "the repository" now names; and a proposed row has no host repository at all, so a link to GitHub would be dead for exactly the state this redraw exists to express. The host is one click further, from the link-out on that row — drawn below, so the whole path is visible in one panel. Rendered in the destination's own vocabulary (design/repository-set/): role pill, establish state, owner/name link-out, helper line.

5A repository that does not EXIST yet — a reference to a proposed row.

LEFT: the state the reference model made expressible (MOTIR-3037 §A3). A card planned before its repositories existed used to carry a role — a word with no row behind it, drawn muted and unlinked because there was nothing to point at. It now points at a real project_repository row, so the name is a link like any other and the row carries its proposed state beside its role. The delivery word is Not created, never "Awaiting": awaiting promises a pull request someone could open, and this repository has no default branch to open one against. The action is on the establish step, not on GitHub. RIGHT: a type: decision card renders the field identically — a planning convention, not a display rule.

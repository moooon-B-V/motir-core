The repository SET on the work-item detail page

MOTIR-2725 · MOTIR-2413. A work item records an ORDERED SET of repositories; its first element is the PRIMARY that a dispatch routes to, and the item is not complete until every repository on the list has a pull request merged onto that repository's own default branch. The rail answers where does this ship, and has it?; the shipped Development section answers which pull request? — and gains one row it never had, for a repository that has none. Rail measured at the shipped 18rem (app/(authed)/items/[key]/page.tsx).

0THE DOOR — where the field sits in the shipped rail.

The field has no button and no menu item: its access path IS its position, so that is the thing to draw. It lands after Estimate and before the collapsed Provenance disclosure — last of the always-visible fields. Reasoning: it is read at DISPATCH and REVIEW time, not at triage time, so it must not push Status, Assignee or Priority down the rail; but it is more actionable than provenance (it gates completion), so it stays expanded rather than joining that disclosure. Neighbours dimmed; the shipped order is CoreFieldsPanel.tsx's.

2bA merge whose branch Motir never recorded — the third state, and it HOLDS.

Rows mirrored before the completion gate began recording base branches carry no branch at all, and a null must read as UNKNOWN in BOTH directions: it does not prove the work reached the trunk (that would complete a card on a stranded merge), and it does not prove it did not. So the repository is neither delivered nor outstanding — it is unknown, it holds the card, and the surface says which question a person has to answer. This state is finite and shrinking: every merge from now on records its branch.

4No repository — a deliberate state, not a hole.

Most cards are here, and the field is optional by design. The value reads None — the shipped word every unset rail field uses — and one muted line says the absence was allowed rather than overlooked. No warning tint, no "+ Add repository" call to action, no required marker; the chevron is the same affordance every editable rail field carries.

6Editing — a bounded multi-select, and one radio for the primary.

The write layer validates every element against the project's repository domain, so this is a bounded picker and never free text. The only ORDER decision a person makes is which repository is primary — that is the only position the data acts on — so there is no drag handle in a 288px rail. Opened by the same chevron every editable rail field carries; the success response is the confirmation and the cell keeps its optimistic value.

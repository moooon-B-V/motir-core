The To fix tag and banner: RUN DIED (MOTIR-6878)

Design asset for MOTIR-6878. A DELTA on MOTIR-6608's published to-fix--tag-and-banner.mock.html: the fifth reason, run died (run_died), on the tag, the item-page banner and the To fix filter. The tag is unchanged in form — the solid danger fill with Wrench — and names the reason only in its accessible name and title: To fix · run died. The banner says when the run was last heard from and POINTS AT the run-died marker in Development (#development); it carries no command and no button. Spec: design-notes.md § The TO FIX tag and banner: RUN DIED. The words in code are MOTIR-6880's.

ACME-14's run died on a branch whose checks are GREEN — so there is NO CI glyph (a passing CI badge draws nothing, ciBadgeState), and the tag alone says the card is stuck. That is the case the tag exists for: a dead run's pull request may be green. ACME-22's checks are red, so the CI glyph (title cell, CircleX in a rose tint) and the tag (status cell, the solid danger disc with Wrench) both draw, in two different columns. Hover or focus names the reason: To fix · run died. The status is In Progress — a dead run never moves its card.

The banner keeps ToFixBanner's frame, disc and link, and drops its lead and its CopyableCodeBlock for this reason: the run-died marker in the Development block (MOTIR-6529) already carries motir continue and Continue hosted (MOTIR-6789), and one page must not hold two copies of one control. Every variant's link is a real href="#development" with the same scroll-and-focus as today; only its words change — See how to continue it, or See how to start over when nothing was pushed. The time is deadRun.lastHeardAt, relative, with the instant in its title.

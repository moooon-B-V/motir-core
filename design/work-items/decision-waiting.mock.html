The decision-waiting marker (MOTIR-5875)

Design asset for MOTIR-5875 (story MOTIR-4908). A member meets a work item on a board card, a List or Tree row and the item page header before they open anything. Each of those places gets ONE marker that answers two questions: is a decision waiting here? and is it waiting on me? The marker has exactly three states — Yours (loud), Someone else’s (quiet), None (nothing). It is Pill in the two tones the primitive already has: awaiting (the band’s own yellow) and neutral. The marker retires the board’s Awaiting acceptance pill. The spec is design-notes.md § The DECISION-WAITING MARKER (MOTIR-5875).

Panel 1 — the three states on a BOARD CARD (the label form)

Yours — loud, a call to act

Someone else’s — quiet, names who

None — unchanged (the shipped card)

Loud and quiet differ in THREE things, never in text alone: the tint (--el-tint-yellow fill vs the neutral chip’s --el-chip-bg + --el-chip-border), the ink (--el-text-strong vs --el-text-secondary) and the glyph’s SHAPE (Stamp vs Hourglass). The card is ONE <button>, so the marker is static — it is not a second control — and the card names it through aria-describedby, because the card’s own aria-label would otherwise hide it from a screen reader.

Panel 2 — the EXCLUSIVE slot’s precedence: Yours › Blocked › Someone else’s › priority, and the CI badge beside it

Blocked AND a gate that is yours → Yours

Blocked AND a gate someone else decides → Blocked

Yours + the CI badge (the badge stays)

Someone else’s + the CI badge — the row wraps

The slot holds ONE of four, in this order. Yours beats Blocked because it is the only one of the four that asks the reader to act, and acting on it is possible while the card is blocked. Blocked beats Someone else’s because the quiet marker is context the reader cannot act on, and a blocked card’s own readiness is the more useful fact on a board. The CI badge is NOT in the slot — it sits immediately after it, as it does today (board-card--ci-badge.mock.html panel 1), and the row already wraps.

Panel 3 — SEVERAL gates on one card, the CARRIED merge gate, and the RETIRED “Awaiting acceptance” pill

A design card with an OPEN pull request — design gate + merge gate → ONE marker

Two gates: one routed to you, one to Ada → Yours

RETIRED — today’s story in review

→

…the same story after this design (its acceptance gate is yours)

Any gate that is yours makes the card yours; otherwise the card is someone else’s. A pull-request merge gate CARRIED by a primary (the design, decision or acceptance gate that leads a Development block) is excluded exactly as the To-approve tab excludes it (CARRIED_MERGE_GATE_EXCLUDED), so it never adds a second marker. The Awaiting acceptance pill said the same fact as an awaiting acceptance_result gate — every pending receipt raises one (persistEvidence → reconcileGatesFor) — so the marker replaces it, and boards.awaitingAcceptance is removed.

The glyph sits AFTER the status pill in the same 108px cell (gap-1.5, shrink-0). Loud is the Stamp glyph on an 18px --el-tint-yellow disc; quiet is the bare Hourglass in --el-text-secondary. Each is role="img" with its sentence as accessible name and title — Awaiting you — design approval, Waiting on Ada Lovelace — pull request approval. Measured, it does not fit 108px: Implemented (the widest default status, and it carries its own glyph) renders at 113.6px — already 5.6px wider than its 108px track today, spilling into the row’s right padding — so pill + 6px gap + 18px marker is 138px. The Status track widens 108 → 144px. The row minimum moves 1204 → 1240px: at 1280 the slack falls 76 → 40px and nothing clips; at 1200 the row already scrolls today and scrolls further. The notes carry the arithmetic.

The marker sits in the EYEBROW, after the breadcrumb — the slot the Archived chip already uses for a state tag — not in the right cluster, which holds verbs (Plan, Watch, ⋯). It is a real <button> with a trailing ArrowDown: it takes you somewhere on this page and does nothing else. It is part of the page’s EARLY tier, so it is on screen before the late sections stream. Below md the eyebrow’s flex-wrap puts it on its own line; the name truncates, the glyphs do not.

The decision-waiting marker — design

Every section that draws a gate’s frame carries data-decision-anchor="<kind>" on its section card, so the destination is WHEREVER that kind is drawn — the table above is what that yields today. Press: scroll the anchored card into view (block: "start", smooth unless reduced motion) and move focus to it (tabindex="-1"). B: if the anchor is not in the DOM yet, scroll to the late stack’s fallback, swap the trailing glyph for a spinner, set aria-busy and announce Opening the design approval…; when the anchor mounts, scroll and focus once, and restore the glyph. If the stack settles with no anchor (the reader cannot see the section), the marker stops waiting and stays where it is — it never opens the overlay.

Opening the card renders QuickViewFolderControl in flow: the removes it from note whenever the item has a work-item parent, then FolderPickerPanel in file mode. The checked option is the item's OWN folder — No folder for an item placed through its root — so picking it writes nothing, and picking 2025 files the story directly (out of its epic, into the same folder). Saving is the rail's shipped grammar: the values change at once (Parent to None), and every rail control is disabled until the write answers (disabled={isPending || readOnly}). After a success the card closes on its new value; the page draws no confirmed check.

The folder path is ONE segment, and it leads. It follows the identifier with the shipped · separator, before the ancestor chain; inside it the folders join with ▸, the separator the Folder field and the picker already use, so a path reads the same everywhere. Text, not a link (decided). Nothing in the product takes a reader to a folder: app/(authed)/items/page.tsx reads no folder parameter (git grep -n "searchParams.*folder" origin/main -- 'app/(authed)/items/' returns nothing), so a link would need a destination this story does not build. A work-item segment keeps its link, its type glyph and its hover; the folder segment has the folder glyph, --el-text-secondary ink and no hover, so the two never read as the same kind of thing. A visually-hidden Folder: prefix names it for assistive tech, and the landmark is labelled Folder and parent work items whenever a folder segment is present. Long paths stay inside the shipped min-w-0 flex-1 cell: segments wrap onto a second line, and a single segment wider than the cell truncates with the full path in its title. A filed ROOT gets a breadcrumb for the first time (today a root renders none), holding only its folder.

One more row in the registry's grammar, no new primitive. Folder is the last entry of the field menu's Other group, after Component — its registry position (FILTER_FIELDS, registry order is menu order). Its value editor is the shipped MultiSelectPicker: every option and every chip is labelled by the folder's PATH with the folder glyph, because two teams can both have a 2025. Under a list operator one line says what the predicate does: Folders inside a chosen folder are included. is empty / is not empty collapse the value slot, as every nullable field's do. A deleted folder is the shipped Unknown value chip and notice, matching nothing. The listbox reads the project's folders bounded at FOLDER_PICKER_MAX (1000) and says so when it stops; a project with no folders gets one quiet line. The applied chip reads Folder + the operator + the paths. The automation rule editor mounts the same FilterConditionBuilder, so its conditions gain the identical row.

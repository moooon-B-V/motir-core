GitHub integration — connect / settings · repo selection · PR & CI status

Story 7.10 · MOTIR-889 (design gate). The GitHub surfaces for the status-sync + review loop: a workspace connects to GitHub through the verified GitHub-App model — two independent grants (know my identity · pick my repos) — after which linked pull requests surface their PR state and CI result directly on the work item. Placement is Settings → Organisation → Git (the connection is ORGANISATION-scoped — see the amendment below; it was workspace-scoped when this asset was drawn). Composed only from shipped primitives — Card, Pill, Button, EmptyState, Switch, the settings-area shell — with colour via --el-* tokens and shape via element-semantic tokens. Five panels: (1) not connected · (2) connected + repos · (3) PR/CI on the issue · (4) empty + revoked-error states · (5) the explicit item→PR link (MOTIR-1595) — the manual override of the auto-resolver, on the detail page's Development card.

AMENDED — MOTIR-4672 (Story MOTIR-4669), 2026-09-05: the tier moves. A repository is connected once, to the ORGANISATION; which projects use it is visibility configuration. Panels 1–5 keep their layout and are re-read at the new tier — the surface was right, the tier was not. Two panels are added: Panel 6, Settings → Organisation → Git, carrying the org’s whole repository inventory with each row’s index state and Used by N projects drawn at rest; and Panel 7, the org-level removal for GitHub, where the disclosure happens before the link-out. GitLab’s in-app confirm is the sibling half in design/gitlab/gitlab.mock.html.

Panel 7 · Disconnect from the organisation — GitHub: the disclosure happens BEFORE the link-out, because there is no dialog left to show once the admin is on github.com

Disconnect moooon/motir-ai from the organisation

Which repositories Motir can read is the GitHub App’s own screen, so the removal happens there. Here is what it will do.

Atlas and Beacon lose this repository. It is removed from every project in the organisation, not only the one you came from.
The code index Motir built from it is kept for 30 days. Re-selecting the repository before then cancels the removal; after that, re-adding it means a full index.

This is NOT a permanence warning, and it must not become one. CODE_GRAPH_RETENTION_WINDOW_DAYS is user-facing, repo_disconnected is windowed, and the shipped copy already promises that re-selecting cancels the removal — so a screen saying “this cannot be undone” would be false, and false in the direction that teaches people to click through warnings.

The 30 above is the rendered value of an interpolation, not a typed number: the sentence is {days} bound to CODE_GRAPH_RETENTION_WINDOW_DAYS (lib/codeGraph/offboarding.ts), exactly as the shipped github.repos.codeIndex string already binds it. Never retype the number.

The two removals do not look alike. This one is an org-wide act that finishes on github.com, so it is a disclosure with a link-out. GitLab’s is in-app and gets an ordinary destructive confirm — drawn in design/gitlab/gitlab.mock.html. The PROJECT-level removal is a quiet row action whose copy reassures, and it belongs to design/repository-set/ (MOTIR-4674), not here.

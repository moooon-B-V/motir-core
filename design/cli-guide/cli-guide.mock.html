The Motir CLI

Install it, sign in, point it at your project, and hand one work item to your own coding agent — in about five minutes, without cloning anything.

Before you start

A Motir account, and Node ≥ 22. That is the list. You do not need a checkout of Motir itself, and you do not need to mint a token by hand.

1Install

Motir ships as a global npm package. Node ≥ 22, ESM — pnpm add -g and yarn global add install the same thing.

install 
npm install -g @motir/cli
motir --help

2Sign in

motir login prints a short code, opens Motir in your browser, and waits for you to approve it there. Nothing has to exist on this machine first.

sign in 
motir login
◆No browser on this box — an SSH session, a container? The code and the URL are printed either way: open the URL on any device and enter the code. For an unattended agent set MOTIR_TOKEN instead.

3Link your workspace root

The workspace root is the folder your repo checkouts live under. Linking it writes a .motir.json there — server, workspace, project — and every command finds it by walking upward, so any command works from inside any checkout.

link 
cd ~/projects/acme      # the folder holding your checkouts
motir link --project ACME

.motir.json holds no secret, so it is safe to commit. If your workspace has exactly one project, motir link alone is the whole step. An empty folder is first class — bind it and go.

4Check it

One read-only pass that answers *is my setup correct?* before a dispatch stops halfway through. It exits non-zero when a hard check fails, so motir doctor && motir auto is a usable gate.

preflight 
motir doctor

It never reads your secret: the credential checks ask only whether a path exists or an env var is set. What each row means is in the reference.

5See what is ready

Get your bearings before you pick anything up — where the project stands, what the sprint holds, and what can start right now.

read 
motir status      # ready / in-flight counts + the active sprint
motir sprint      # the active sprint, and what blocks what
motir ready       # what can be picked up right now

motir sprint and motir ready print dependency edges in their own columns, so you can see which item unblocks the most before choosing one.

6Dispatch one item

Read the card first — motir show gives you its fields, its readiness, its dependency edges and, for a story, its children in build order. Then claim it.

dispatch 
motir show MOTIR-42       # the item you are about to hand an agent
motir next --print        # claim the top item, print its prompt

--print writes the prompt to stdout and everything else to stderr, so motir next --print | pbcopy copies the prompt alone while you still see the context. Paste it into whatever agent you like. When its pull request is merged, close the item out:

close out 
motir done --via in_review MOTIR-42
◆Want Motir to launch the agent for you? motir next --agent "<your agent command>" runs it on the prompt, and motir auto drains the whole ready set unattended. Motir is BYOK — it never reads your agent’s key.

Where Motir keeps things

Motir keeps exactly two files, and only one holds a secret.

files

Path What it holds
~/.config/motir/config.json Secret — never commit. The credential store, chmod 600 inside a 0700 dir, keyed by server URL.
.motir.json (workspace root) No secret — safe to commit. The link: server, workspace, project, and the optional repo-path overrides.

The CLI talks to https://app.motir.co unless you tell it otherwise. Self-hosting? --server <url> beats everything on any command; motir help environment prints the whole ladder from the shipped code.

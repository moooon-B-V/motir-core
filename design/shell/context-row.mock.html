The shell's context row — org › workspace › project, the rail head, and the brand tile

MOTIR-2555. The bar gains the PROJECT as its last tier, the left rail gives it up, and the brand mark gets a field of its own. Every control in every frame is shipped markup; what this design decides is the arrangement and the responsive prefixes. Every number was measured in Chromium against the build's own compiled CSS — the harness is reproduced in design-notes.md.

Panel A · What ships today, rendered

The bar carries org › workspace; the project lives in the rail. Note the first frame: at 320px — the narrowest viewport the app supports — the shipped bar still overflows by 47px. MOTIR-2374's budget reserved a 68px floor for the tier nav, but the two shipped tiers cannot compress below 112px, so that floor was never reachable. Closing this is a side effect of the below-md rule in Panel B, and the finding belongs to this pass.

Panel B · The target — one path, three bands

The row has one elastic element and three things that now want it, so the answer is a LADDER rather than a layout. It follows the breadcrumb convention every mature tool uses: the most specific tier never leaves, and ancestors collapse from the left — first to a mark, then out of the bar entirely and into the drawer, which carries org › workspace at every width. The workspace tier keeps the reveal rule it already has (shown only when the org holds ≥2 workspaces), so a single-workspace org reads org › project wherever it appears.

Panel C · The three states the project tier inherits

The rail head resolved three states no other rail row needs, and all three move with the control. The archived pill is shrink-0, so the NAME truncates around it rather than the pill being dropped. The no-project state cannot be the rail's full-width lavender card in a horizontal row, so it takes the ghost-button grammar the other tiers use — keeping the accent + square and the label, and opening the same CreateProjectModal.

Panel D · The amended budget — measured, not reasoned

room = viewport − gutters − right cluster − the left cluster's NATURAL width. Negative means the project name truncates, which is by design — it is the elastic element. ovf is real horizontal overflow and must be zero. Measured in the WIDEST right-cluster state (a public project with AI configured), because that is the state that sets the budget.

The rule for the next tier. The bar's path is closed at ONE tier below md, TWO from md, and THREE from xl. A tier added to the path is an xl-and-up tier by default; to appear earlier it must displace one, and the displaced one needs a drawn home — which is the drawer header, and the reason that header keeps the full ancestor path at every width.

Panel E · The rail head, after the project leaves

The rail answers where inside this project can I go. Its head was answering a different question, which is why it needed three states nothing else in the rail needs. All three move to the bar and the default-area head is removed — the rail starts at its first nav section. The settings and account areas keep their own headers (SettingsSidebarHeader, AccountSidebarHeader) untouched, and the collapsed rail's 32px project avatar goes with the rest.

Panel F · The brand tile

The 32px rounded box already exists in TopNav.tsx and is simply unpainted. It gains an --el-surface field and an --el-border hairline; the glyph KEEPS --el-accent-on-surface — the token whose name is literally this composition — so .brand-glyph's global rule, shared with the auth, explore, public and OG surfaces, is not touched by this story at all. The hairline divider that followed the mark is REMOVED: the tile's own edge now says what the divider said, and it returns 9px to the row.

So it sits OUTSIDE the scroller, on the rail column’s own foot — the same instrument, and the same reasoning, as Part XIII §8’s pinned decision. The audit line it replaces scrolled and could: Created / Updated is a fact you go looking for; the count is a fact you must not be able to miss.

Panel 8 · both themes

Dark — verified in Chromium, and NOT drawn as a nested scope

The stylesheet above is Tailwind’s real output for this document over @motir/design-system/theme.css, so every --el-* here resolves from the shipped layers — declared on :root and re-declared under [data-theme='dark'], never only inside one of them. Flipping <html data-theme="dark"> flips the whole board, and it was rendered that way in Chromium at 1240px before this asset landed: the changed chip resolves --el-diff-moved to #1a2a3a, the header’s three op chips and the pinned foot line all read correctly, and --el-text-strong stays legible on the dark tint.

No NESTED dark panel is committed, and that is deliberate — Part XIII §9 recorded the same finding and this Part repeats its answer rather than working around it. The dark-parity guard (tests/design-dark-parity.test.ts) renders with happy-dom, which does not resolve var() through the shipped [data-appearance-scope] block, so a nested [data-theme="dark"] element passes only when the asset re-declares --el-page-bg with a CONCRETE value — which is exactly the local-token declaration this board is built to avoid. The dark value is STATED in Panel 6’s token table instead, beside its Tier-0 source, where it is checkable without an engine.

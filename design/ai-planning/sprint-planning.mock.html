The palette entry navigates to /backlog and opens the run in one step, so the action has one implementation and two doors. It is registered in the same command registry the shipped “Go to Backlog” / settings deep links come from — a palette entry is the app’s existing way to reach an in-surface action from elsewhere, so no third surface is invented.

Not drawn on purpose: a left-nav entry. A nav entry is this app’s convention for a first-class project view (Dashboard / Boards / Backlog / Roadmap / Plans). Sprint planning is an action on the backlog’s own objects — the same class as Start sprint and Complete sprint, which also live in-surface (notes.html #99).

A proposed sprint is the shipped SprintContainer with the proposed treatment (dashed --el-accent border, lavender head, Proposed pill) — so the review reads in the exact vocabulary the result will have. Read-only: no drag handle, no checkbox, no ⋯, no Start-sprint. The lifecycle controls appear only once the sprints are real (panel 5). Editing a proposal is deliberately out of scope here — the approve API accepts an edited delta, but the first release approves or discards whole, and re-running is the way to get a different packing.

The code-context surface

MOTIR-1754 · MOTIR-1764. Motir’s loop is plan here → your agent builds → plan the next phase against what was built. The last hop only holds if the code the agent wrote is in the graph — and on the start-fresh journey it never is, silently. This asset draws the two surfaces that make that visible: a durable connect affordance on /code-health, and a per-repository freshness reading on /planning, with an explicit state for planning that happens without code at all.

Drift is stated in COMMITS, never as an age. An old graph on an unchanged repository is current; a two-hour-old graph on a busy one is not. And stale is not indexing — only one of the two is moving, and only the moving one is allowed to invite a person to come back later.

0THE DOORS — where each surface is reached, drawn in situ.

Neither surface is a new page and neither has a menu item: the access path IS the position. The connect aside sits inside the /code-health report the user is already reading — between the health-summary card and the findings card, exactly where design/coding-convention/design-notes.md Panel 1 places the §10.3 aside. The code-context strip sits in the /planning workspace’s right rail, above the composer, so the answer to “what can the planner see?” is beside the thing that is about to use it. Neighbours are dimmed; this asset does not redraw the canvas, the rail’s other panes or the composer — see design/ai-chat/planning-workspace.mock.html.

DConnected but STALE — and not moving.

This is the state the amendment promoted. It leads with the drift, in commits: an old graph on an unchanged repository is current, and a two-hour-old graph on a busy one is not, so an age is not a weaker phrasing of this verdict — it is a different and wrong verdict. It sits one rung above the §10.3 invitation (the token layer’s own warning family, --el-warning-surface + --el-warning edge) and one rung below an error. ⚠️ It promises nothing — no “catching up”, no “shortly”, no “check back”. A stale repository may sit stale for ever. Both ends of the range the one panel must survive are drawn: 1 commit and 312.

VThe four verdicts, side by side — what the code card must render.

MOTIR-1767 returns exactly one of these per repository and the function is TOTAL. None of them reads as an error. They are separated by tint family and glyph together, never by colour alone (WCAG 1.4.1), and none uses a dashed or dotted border for state — that clashes with data-style. ⚠️ A repository whose head is null (connected before the head column shipped, or a provider whose head is not recorded) is UNKNOWN, and unknown renders current — never stale. That is the one place a wrong default would put a false warning in front of every existing user.

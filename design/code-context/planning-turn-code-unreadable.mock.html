A delta on design/code-context/code-context.mock.html (MOTIR-1764), which drew the missing-context state (its panel E: no repository connected or indexed, a standing condition the person can fix). This draws the outage state: the project’s code is connected and indexed, and Motir cannot read it right now. Nothing here edits MOTIR-1764’s states, the Code page or the audit’s “not measured” face.

It composes the plan-change rail that ships — TURN_RENDERERS in components/planning/PlanChangeRail.tsx, its assistant Bubble, the passive marker line, the information notice EarlierNotice and the secondary Try again button the rail already offers on a failed turn. No component is added. Two kinds of turn meet the outage and each gets one face; the notice lives on the turn and is never a page-level banner.

The decision: no sticky page-level banner

Each turn carries its own state, so the second turn gets its own notice. No banner is pinned to the rail head or the page while the outage lasts. A banner would outlive the outage — it would still be there, or have to be dismissed, after the code is readable again — and would teach people to read past it. The rail head and the composer look exactly as they do on a healthy day.

Two turns in the same outage say the same thing twice. That is the point: the statement belongs to the turn it is true of, and a person scrolling back sees which turns could not read the code.

Repositories — a project's TWO registries, drawn apart

The room is a liar today. On the live MOTIR project /settings/project/repositories renders one card that says "This project has no repositories yet" while five repositories are connected, indexed and pinnable on every card. It reads project_repository and nothing else, so the workspace-connected registry — the one that answers for every project that arrived WITH code — is invisible to it. This asset draws what the room must show instead.

Nothing here is a new product decision. docs/decisions/project-repository-set.md's amendment (MOTIR-3086) already decided WHICH repositories a project has, as a layered ladder in lib/workItems/dispatchRepo.ts. The resolver applies it and the surfaces never learned it. So the panels below render exactly the ladder's answer, per project shape — and the ONE thing this asset decides is that the two registries are drawn as TWO sections rather than one merged list, because only one of them can be taken over.

Drawn against SHIPPED reality. The room's island (RepositoriesRoom · TakeoverRow) was RENDERED headless from its own source and the real compiled globals.css before anything was drawn — both its empty branch (the false sentence, reproduced in panel 1) and its row branch. The connected-repository list is the shipped one from /settings/workspace/github, mirrored element for element rather than redrawn. Nothing shipped is reinvented (notes.html #73).

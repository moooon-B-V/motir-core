motir.co — the not-found room, inside the public chrome

Every motir.co surface already wears one chrome; a 404 wears none. This asset draws the ROOM that goes inside it — what a lost visitor is told, and the two doors out — and decides the question the build card deliberately does not answer. The chrome itself is MIRRORED from the shipped components, not redrawn: every measurement below was read off the running site at origin/main 61b9a13.

The two doors, in order

# label href treatment
1 Explore projects /explore primary — Button md, --el-accent fill
2 Go to the homepage / ghost — Button md, no border (see the button block)

Why Explore is primary

Three of the four arrivals (panel 5) are people who wanted a public project — a shared /p/<identifier> link whose owner turned public access off, or an unlisted topic. /explore is the only destination that answers them, and it is a reading surface a stranger can use immediately. The landing is a pitch; it answers only the mistyped URL.

Why exactly TWO

Because the chrome already carries the rest. The bar holds Explore, Docs and Design; the footer holds all nine destinations including the whole Legal column. The room's doors are a ranking, not a menu — they name the likeliest intent and let the chrome carry every other one. That is also why the stock screen is bad: it has no chrome, so it would need everything, and it offers nothing.

Why no Docs door

Docs sits in the bar 57px above the room and in the footer below it. A third door would re-list the nav.

Why no search field

motir.co has no site-wide search. The one search input on the site belongs to /explore and is scoped to the project directory (motir-marketing/app/explore/_components/SearchForm.tsx). Drawing a search box here would invent an unshipped control — the design-reference rule's NONE-exists case. The Explore door carries the reader to the surface that has the search.

The access path — the four ways in

A 404 has no entrance anybody clicks deliberately, so the access path is not a nav affordance — it is the set of ARRIVALS. Every one of these calls notFound() on ordinary input, and the room's one sentence has to be true for all four. That constraint is what produced the copy: not "we couldn't find that document", which is false for three of them.

Arrival 1 — a link from outside

/p/<identifier>

A shared link to a public project whose owner has since turned public access off, or to an item or request that is not public. The routine case, not the exceptional one.

Wanted: a public project → Explore

Arrival 2 — an unlisted topic

/explore/topic/<slug>

A topic slug the API does not list.

Wanted: to browse → Explore

Arrival 3 — an unknown document

/legal/<slug>

An unknown legal slug. Answered by the footer's Legal column, which is on this very page — which is why it earns no door of its own.

Wanted: a document → the footer

Arrival 4 — a mistyped URL

/anythnig

No route matches. The only arrival for which the landing is the right answer.

Wanted: the site → the homepage

What ships today — measured, not described

404 This page could not be found.

Rendered at 1440×900 on origin/main 61b9a13. Status 404, and document.querySelectorAll('main').length === 0. No header, no footer, no brand, nothing that links anywhere.

One room, not four

All four arrivals resolve to the SAME boundary. Next resolves notFound() to the nearest not-found.tsx above the route, and motir-marketing has none anywhere — so one motir-marketing/app/not-found.tsx serves all four, and a per-route variant would need a per-segment file nobody has asked for.

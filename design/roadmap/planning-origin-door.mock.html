Three axes, each doing one job. The fill says whether the artifact exists (mint vs. neutral plate); the corner check repeats it non-chromatically; the label ink — and only the label ink — says whether it opens. That is why the absent state needs no dashed border: the difference a user reads is the missing hue and the missing check, never a hairline (which would also collide with the data-style shape axis). Label ink stays --el-text-secondary on both non-doors — --el-text-faint measures 2.39:1 on --el-surface and fails AA for text.

Why the unconditional “Complete” is wrong. The badge is a claim about the journey's output, but its only evidence is a marker that records the journey ran — so on a project whose pre-plan wrote nothing, “Complete” asserts four documents that do not exist and points at nowhere. Not an error state: the two stages the marker really does attest — Idea and Plan — keep their checks, the strip still reads as provenance, and the neutral No docs chip reports a fact rather than flagging a fault. Nothing is red, nothing asks the user to fix anything.

Required delta — the door must stop its own key event. The wrapper's handler is if (e.key === 'Enter' || e.key === ' ') { e.preventDefault(); onNodeActivate(n.id); }, and a keydown on the button BUBBLES into it — so without e.stopPropagation() on the tile's onKeyDown, the wrapper cancels the button's implicit click and the door cannot be opened from the keyboard at all. onPointerDown already needs the same guard for the pointer path (the shipped in-block doors do that half). Each tile also carries an aria-label naming the document — “Open Understanding your project” — because the visible 10px label (“Discover”) is not the doc's name.

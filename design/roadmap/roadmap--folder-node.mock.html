A folder is never an edge end. It blocks nothing, so no arrow starts or ends on a folder card, and it never takes the cross-blocked chrome. An edge between a filed row and a row at the level in view follows the rule the grouped level already follows (root-non-epic-rows decision 4, MOTIR-3557): a level draws the edges whose blocked end is one of its rows. So the epic above keeps its shipped ghost anchor for the filed bug that blocks it. The one change is the anchor's location line: where it reads the blocker's parent or "elsewhere" today, a filed blocker's line reads its folder path, drawn with FolderPathLabel (glyph + ▸ path, collapsed to 2). The reader learns which door to open. On the folder level (sheet 4), the same edge draws from the bug's side as an ordinary off-level blocker, if the bug is the blocked end.
8 · Decisions the code card would otherwise make silently each with a disposition; full text in design-notes.md
# question decision
1 What leaves the root read? Every filed work item. The roadmap passes the same excludeFiled treatment the /items root does. A filed epic leaves the road and appears inside its folder.
2 Where do folders sit? At the head of the loose band, in their own position order, after the road and before Not in an epic. This is the same rule at every level.
3 What does the card count? Direct contents, folders and work items named separately: 2 folders · 5 items. It is never recursive and never a status tally.
4 Does the 200-row cap count folders? No. The cap and its tile are about work items. A level's folders are read whole, like the folder tree /items reads, and drawn before the tile. "Showing 200 of 794" stays a true sentence about work items.
5 Is a folder decorative? No. It holds real work, so it counts as a choice. A root with one epic and one folder does not auto-descend into the epic, just as grouped-node decision 5 reads.
6 Sprint scope (scope=sprint) Folders are not drawn, and placement is ignored. The sprint view shows the work the sprint committed to. Hiding a committed bug behind a folder door would bury exactly what the view is for. A filed in-sprint row renders where it would if it were unfiled.
7 Search-to-locate A folder card's search text is its name. Locate still searches the level in view, as today. Finding an item inside an unopened folder is unchanged, and is out of scope.
8 Out of scope The run canvas (ids= levels ignore placement by construction; a run's members are drawn as the run took them). The public roadmap (publicProjectsService carries no folder field, by MOTIR-5309's decision). The plan-review canvas crumb (sheet 5).

The /docs index — the area's front door

Story MOTIR-2315 · Subtask MOTIR-2521 — the one surface in this area nobody had drawn: its ROOT. Four panels; review each. Built to ADR public-api-conventions.md Amendment 19, which decided that /docs renders a page (Q1), what it lists (Q2), that the list has one home (Q3), that the page carries NO rail (Q4), and where the two entrances point (Q5).

Panel 1 · /docs — the area's front door, desktop The page is a title, a lede, and ONE ROW PER SURFACE, each with a line saying what it is and who it is for (Amendment 19 Q2). It renders inside the shipped app/(public)/docs/layout.tsx shell — the same marketing top bar and footer every other page in the area already sits in — and it renders no catalogue rail: its body IS the navigation, so a rail listing the same four destinations would put them on screen twice, with the shorter copy in the more prominent position (Q4). Compare the content column's full width here against Panel 3's right half. The rows are NOT grouped: four rows under category headings is a heading per one-and-a-half rows.

Panel 4 · THE ACCESS PATH — both entrances, before and after Amendment 19 Q5. Neither entrance is a new element: the top bar's Docs item and the footer's product link both already exist and both already resolve — they simply point PAST this page, at /docs/api. What changes is the target of each, and the footer's LABEL, because a link reading “API docs” that opens the whole documentation area is the same mismatch this story is fixing one layer down. This design owns only these two items; the bar and the footer belong to design/project-square/.

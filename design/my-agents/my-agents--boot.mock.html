MY AGENTS, delta — watching an agent boot — /my-agents?agent=<id>

MOTIR-7393 · MOTIR-7395. It amends design/my-agents/my-agents--panel.mock.html (MOTIR-6937) Panels 2–4 and MOTIR-6868’s list mock Panels 2 and 4, which stay records and are not edited. It draws only what the boot read-out changes: Create closing at once, the read-out in every step state, the failed read-outs with their way out, a wake, a deletion mid-boot, the summary once running, the booting list row and the narrow width.

Every state is the decision’s — docs/decisions/agent-instances.md AMENDMENT 6 (MOTIR-7394): steps provision · machine_start · clone (one per owner/name) · terminal_check · ready, states waiting · in_progress · done · failed · skipped. The copy is this card’s.

1THE ACCESS PATH — New agent → the dialog → Create → the dialog is gone and the new agent’s panel is open on its boot.

Unchanged up to the press: the page header’s New agent opens the create dialog (MOTIR-6868 panel 2), whose fields, picker and price line this delta does not touch. What changes is how long Create is pending. The server now answers at starting as soon as the machine is provisioned (AMENDMENT 6 §5) — about a second, never the length of the boot — so the button’s own loading face lasts only that long.

On the answer the dialog closes, the list gains the new row in Starting, and the panel opens on it: the address becomes /my-agents?agent=<id> (the same replace a row click makes, MOTIR-6937 panel 1), and focus moves to the panel’s heading. The read-out sits between the header and the tab row. A refused create is drawn once (C) to show what did NOT change: the dialog stays open, the input kept, the refusal above its footer.

For a wake, the panel’s own Wake (or opening a hibernated agent, MOTIR-6937 Q6) opens the same read-out — panel 7.

2THE READ-OUT, IN PROGRESS — one row per step, each state its own glyph and ink.

The five steps of AMENDMENT 6 §1, in order, one clone row per repository in the project’s order: Machine provisioned · Machine started · Cloning owner/name … · Terminal checked · Ready. Above them, the read-out’s head: Booting (a wake: Waking) and the whole boot’s clock, 0:44.

Waiting is quiet: a hollow circle, secondary ink, no time. Done is quiet too: a success tick, secondary ink, its duration (3s). In progress is the ONE row that stands out: the sky tint with strong ink, the loader glyph, and a ticking clock (0:41) — the clock is what reads as live, so nothing changes colour and the reduced-motion reader loses nothing (the loader’s rotation is a transform, and stops under prefers-reduced-motion). Each row carries its state in words for a screen reader, and a polite live region announces a step only when its STATE changes, never each tick.

8DELETED MID-BOOT — the read-out’s last word before the row leaves.

Delete… is enabled during a boot (AMENDMENT 4). Confirming it closes the attempt: the step in progress becomes failed with detail deleted (AMENDMENT 6 §4), and the stream’s last frame is done · deleted. That is the read-out’s last word, Deleted while booting, under the head Deleted — this panel closes; the panel fades and closes exactly as MOTIR-6937 panel 4’s deleting does, and the list keeps the row in Deleting until it is gone. A deletion is the reader’s own act, not a fault, so this row takes NO danger hue: it is drawn as skipped (struck, secondary).

1THE ACCESS PATH — the marker on the row, and Update in the panel header beside Hibernate and Delete.

On the list, the Coding agent cell gains the agent’s version (mono, secondary) and, when a newer image exists, the Update available → <version> marker beside it (sky tint, strong text — AA on the tint). The row stays the door to the panel (MOTIR-6937 panel 1, unchanged).

In the open panel the same version line sits under the meta line, and Update is the FIRST action, before Hibernate and Delete, shown only while an update is available. It opens the confirmation (panel 3). Up to date shows the version and no marker; could not check is a quiet grey chip, never a claim that the agent is current (decision Q1).

3THE CONFIRMATION — naming both versions, what is kept, and what happens next.

Pressing Update opens the page’s own dialog shape (the Delete confirmation’s, MOTIR-6937 panel 2). It names the current and the target version and lists what is KEPT. A running agent is told it restarts; a hibernated one that it takes the new version the next time it wakes. Not now closes it and calls nothing.

Running agent

Update yue-claude to 0.10.0?

Claude Code 0.9.0 → 0.10.0. The agent restarts on the new version, which takes about a minute. It keeps:

  • its home and every file in it, including the cloned repositories;
  • its coding agent’s sign-in;
  • its chat sessions.

If the new version doesn’t start, the agent goes back to 0.9.0 and tells you why.

Not now Update and restart
Hibernated agent

Update yue-codex to 0.10.0?

Codex 0.9.0 → 0.10.0. It stays asleep and takes the new version the next time it wakes. It keeps:

  • its home and every file in it, including the cloned repositories;
  • its coding agent’s sign-in;
  • its chat sessions.

If the new version doesn’t start at that wake, the agent goes back to 0.9.0 and tells you why.

Not now Update on next wake

4UPDATING — the restart in the terminal, every action disabled until the agent is back.

While the agent is Updating, the terminal shows MOTIR-6937’s Reconnecting… face (panel 5, unchanged): the machine reboots onto the new image and the shell comes back. Update, Hibernate and Delete are disabled (aria-disabled) and the panel follows the agent until it leaves the state — to Running on the new version, or Running with the rollback line (panel 6).

7FAILED AND ROLLED BACK — back on the old version, the reason in words, the update still offered.

When the new image fails its check, the agent is Running on its previous version (decision Q4). The reason sits under the version line in the base asset’s .reason style (danger on surface, AA), and Update stays, so the owner can try again once a fixed release lands.

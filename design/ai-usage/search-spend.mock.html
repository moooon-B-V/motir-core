Search spend on the usage dashboard (MOTIR-4554 · amendment to 7.2.10)

An amendment to design/ai-usage/usage.mock.html, not a redesign of it. Every quantity on that asset is token-denominated; a search has no model and no tokens, so it cannot be a row in the per-model breakdown and cannot be a token count anywhere. This asset answers the three questions that follow — how the figure behaves under the DRILL, what a search row looks like in the ACTIVITY LOG, and what happens to the UN-ATTRIBUTED remainder. It is also the answer to the note that asset's own Panel 5 left: “search is rendered nowhere at all … nothing on the surface saying so.” Every figure is a named field of OrgUsageDTO.search / .searchRuns (MOTIR-4555). Toggle dark mode to verify --el-* token parity.

1 · IN PLACE — the shipped stat row at real width, with a FOURTH card. The three shipped cards are copied verbatim and are untouched. The new one sits beside them so the reader judges it in its real neighbourhood. Every figure carries a SCOPE LABEL — the decision this panel exists for. At org scope the labels agree and nothing looks unusual; panel 2 is where they come apart, and the label is what makes that legible instead of mysterious.

A web search is charged per search, at 1 credit each, and has no model and no tokens — so it never appears in the per-model breakdown above. It is shown as its own figure for the same reason.
2 · THE DRILL — and the decision this asset exists to make. Scoped to one project. OrgUsageDTO.search is org-level and scope-independent (a search made outside any run has no project to attribute to), while searchRuns.attributedSpend DOES narrow with the drill. So the two search figures no longer agree, and a number that silently ignored the selector above it would be the surface lying quietly. Each figure states its own scope, in the same place, in the same words: Whole organization or Follows this scope. Both are true and both are useful; what is not acceptable is being unable to tell which is which.

3 · The activity log, holding a MIX. Search rows interleaved with token rows in ONE paginated list, drawn against real neighbours so the mixed table is what gets judged — not an isolated row. Two things are decided here: a search row carries the NEUTRAL chip with the search glyph, never a --el-tint-*, because it is not a job kind and all six tints are already spent on this surface (five of them on job kinds — reusing sky would make a search row and an expand run read alike); and the token columns carry an EM-DASH, not a zero, because a search has no tokens at all and a `0` would claim it used none.

4 · The UN-ATTRIBUTED remainder, and its ZERO case beside it. Attributed rows will not sum to the org total, because searches made outside a run still debit (MOTIR-2778 §4 makes two such arrivals legitimate). That difference is a real, explainable quantity — not a reconciliation failure — and an unexplained gap between a total and its rows is precisely the complaint this story exists to end. It is drawn as a residual ROW in the same credits column the rows above sum into, never a footnote: a number the reader can add up by eye is a number they can trust. At zero the row is ABSENT, not rendered as “0” — a residual line reading zero invites the reader to look for a problem that is not there.

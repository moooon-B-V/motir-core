Panel 1 — The logomark: the wave band (current)

No letterform. The mark is not an M and is not derived from one — an initial says only what the product is called. The current mark is the wave band: Yue supplied it as a reference drawing on 2026-08-05 and asked for it to be used as the logo for now, so it was traced from that image rather than constructed. Everything it costs and everything it does not yet have is recorded below, honestly, because a provisional mark that is documented as provisional is safe and one that quietly becomes permanent is not.

The wave band

Traced from Yue's reference; closed at both ends and filled solid.

How it was made. The reference was read pixel by pixel rather than redrawn by eye: the image was thresholded to the white curve alone (dropping the grid), the two edges taken as the two runs in each column — 318 of 324 columns gave both cleanly — and Catmull-Rom cubic Béziers fitted through samples every 6 px. The two edges are then joined by a straight cut at each end and filled. An overlay against the original shows the fill sitting exactly between the two curves with no drift.

One path, fill="currentColor". It carries no colour of its own, so it takes whatever color the surface sets — which is how it follows the theme (§4) and a data-palette swap for free.

What this mark does not yet have

  • It is traced, not constructed. Every other candidate on this card is generated from a rule — a Hasse diagram, a hypocycloid, a Brunnian link — so it can be re-cut at any size, weight or proportion from its own definition. This one is a fitted outline of a drawing. It cannot be re-derived; it can only be re-traced. If it stays, someone should re-author it as a constructed curve.
  • The two edges are not parallel. The vertical gap runs ~156 units at the trough and ~196 at the peak, and the lower edge's amplitude is 108 against the upper's 146 — so the band is not of constant width; the lower edge is a flatter copy. This was traced exactly as drawn, on instruction. If the difference was accidental rather than intended, regularising it is a small change and worth making before it ships.
  • At 24 px and below it reads as a letter M. The two peaks and the central dip land squarely in M territory once the detail closes up — visible in the scale ladder in Panel 2. That is the one thing this card ruled out at the start, and it is the reason to treat the mark as provisional rather than settled. It reads as an abstract wave at 40 px and above, and on the app tile.
  • No prior-art check has been run on it. The check recorded below was performed against the lattice. A wave band is a much less crowded shape than a concentric rhombus, but "less crowded" is not "checked" — and MOTIR-2267 (trademark clearance) now needs to search this shape, not that one.

On record — the lattice, chosen and then set aside

A · Lattice

The Hasse diagram of a fork–join, nested inside itself at exactly half scale. A plan is a finite partially ordered set and the rhombus is how mathematics draws the smallest non-trivial one — one start, two independent paths, one convergence; nesting a second at half scale says the other true thing, that a plan is self-similar. Chosen on 2026-08-05, then set aside in favour of the traced wave band. Its argument still stands and so does its prior-art record, which is why both are kept here rather than deleted.

Prior art — the check that was run on the LATTICE

Kept because it is the only prior-art work done on this card so far — and because it is a worked example of the check any mark needs. It concerns the lattice, not the wave band. A plain concentric rhombus is one of the most occupied geometric marks in existence:

Mark Construction Distance from a plain concentric rhombus
Binance A large diamond with an intersecting form cut out of it — four outer corner elements around a central diamond The closest, and the most dangerous. Adjacent sector, and at small size the gestalt is exactly diamond-inside-diamond
Renault (2021) Two interlocking diamonds, flat monoline, weaving through each other Different construction, but the most famous monoline diamond mark there is
Umbro The "double diamond" — overlapping rhombi, since 1924 The mark that defined the nested-diamond category
Mitsubishi Three rhombi arranged into an implied fourth The most recognised rhombus mark in the world
Stock 100,000+ "diamond shape logo" assets; "diamond inside a diamond" is a documented stock trope explicitly sold to tech startups The shape carries no ownership at all on its own

The conclusion, and the fix. The idea behind the mark is Motir's; the plain concentric drawing of it is nobody's. Adding the vertices moves it from decorative shape to the mathematical object it actually is, and walks it out of that neighbourhood without changing the idea by a single degree. Four alternatives were drawn and compared — breaking the edges at the vertices, breaking both rings, a square inside the diamond, and an outer ring with nodes but no inner rhombus. The nodes-on-the-outer-vertices treatment was chosen: it is the smallest change that buys the most separation, and the only one that keeps the mark legible at 16 px.

The three alternatives, kept on record

D's motion, kept for the record. Both motions re-derive the outline from a changed curve rather than rotating a finished picture, and each frame is a single path. If a motion identity is ever wanted, this is the candidate that already has one.

Travel — the wave moves through the band

The phase advances; the band stays where it is. This is what a wave is: the shape moves, the medium does not. One full period is a seamless loop — 10 frames, 2.2 s.

Frequency — the curve changes its period

One period stretches to two and back, amplitude easing down as it does. The plan is not a fixed rhythm; the thing that changes it is one number.

Motion is decoration, never information. The mark animates only where it is already decorative and large: the OG card, the marketing hero, a loading state. It is static in the shell, in auth, in email, in the tab strip and at every size below 40 px. And all of it sits behind prefers-reduced-motion — the same gate globals.css already puts on the Plan-with-AI shimmer and the FAB pulse — with the static mark as the reduced-motion state.

Considered and dropped: the isometric cube (the Hasse diagram of B₃, which would have been the mark one dimension up) and the Penrose tribar (locally consistent everywhere, globally impossible — a precise description of a plan that does not close). Both are mathematically apt and both were built and rendered. Both are also among the most heavily used marks in software — the cube is lucide's own Box — and a brand mark that reads as a stock icon is not worth the idea behind it. Three more were built, rendered and dropped while chasing a three-dimensional form: the astroidal ellipsoid (|x|2/3 + |y|2/3 + |z|2/3 = 1), too complicated at a faceted mesh of 80 paths; the hypocycloid plate, candidate B cut thick and tilted; and the wave as a shaded solid, which had the volume but not the elegance. A diagonally-rolled wave was also drawn and rejected for reading plainly as the letter Z — the very thing this card ruled out at the start.

CURRENT (Yue, 2026-08-05): the wave band — provisional. Everything from Panel 2 onward is built on it, and it is safe to ship internally: one path, currentColor, theme- and palette-following, and strong at 40 px and above. Two things must be settled before it is treated as final — the M-reading below 40 px (§1), and a prior-art check on THIS shape rather than the lattice (MOTIR-2267). MOTIR-1140 therefore stays open. The lattice and the three alternatives are kept above so that reopening the choice costs nothing.

Panel 2 — Construction, clear space and minimum size

24-unit grid · the dashed box is the mark's true extent (20.6 square)

viewBox
0 0 24 24 — the same grid every lucide-react icon in the app uses, so the mark drops into any icon slot unscaled.
path
One closed path, ~3.6 kB of cubic Béziers. Source of truth is design/brand/wave-band.svg (native 317 × 313) with design/brand/wave-band-24.svg as the 24-grid cut used here. It is a fitted trace, not a formula — see Panel 1.
how it was fitted
The reference image was thresholded to the white curve (dropping the grid), the two edges taken as the two pixel runs per column — 318 of 324 columns gave both — and Catmull-Rom cubic Béziers fitted through samples every 6 px. The edges are joined by a straight cut at each end. Re-run that trace, don't redraw by hand, if the mark ever needs re-cutting from the original.
paint
fill="currentColor", no stroke. The mark carries no colour of its own — it inherits color from whatever renders it, which is exactly what makes it follow the theme and the palette (§4, and the dark card in Panel 4 is the proof).
extent
x 1.0 → 23.0, y 1.14 → 22.86 on the 24-grid — 22 × 21.7, all but square, centred on (12, 12). Aspect is preserved from the source (317 × 313), so the mark is very slightly wider than tall; do not stretch it to fill a square.
clear space
3 units (12.5% of the box edge) on all four sides, measured from the extent above. A solid form needs less air than an outline of the same size.
minimum size
40 px. Not a legibility floor — the shape survives far smaller — but a reading floor: at 24 px and below the two peaks and the central dip close up and it reads as a letter M (Panel 1). Below 40 px this mark needs either a simplified cut or a different mark.
colour
ONE colour. The mark is monochrome by construction — it never carries a gradient, a second hue or a shadow.

Panel 3 — Wordmark and lockups

face
Inter, weight 700, tracking -0.02em — already loaded by app/layout.tsx, so the wordmark costs no new font payload.
the pin
The wordmark MUST read font-family: var(--font-sans-source), … — the raw FACE variable — and never var(--font-sans), the role token. [data-type='motir-mono' | 'grotesk' | 'mono-technical'] each re-point --font-sans, so a wordmark riding the role token changes typeface when a user picks a type pairing in Appearance. This is not hypothetical: it is what the shipped ExploreTopBar does today (Panel 0a). The mark is brand; the type axis is chrome; they must not be wired to the same variable.
proportion
wordmark font-size = 0.72 × glyph box; gap = 0.33 × glyph box; baselines optically aligned by centring the wordmark's cap-height on the glyph's extent, not on its viewBox. At the 32 px glyph that is 23 px type on a 10.5 px gap.
colour
glyph --el-accent-on-surface, wordmark --el-text. Two tokens, both themes, no exceptions.
where fonts cannot be relied on
next/og renders outside the CSS tree, so the OG template must pass the Inter face through ImageResponse's fonts option (Panel 6). It ships fontFamily: 'sans-serif' today, which is why the current card's "Motir" is set in whatever face the renderer happens to have.

  • The dark variant is a token choice, not a second asset. The glyph paints currentColor and the lockup sets color: var(--el-accent-on-surface), which resolves to #5645d4 light and #7b6ce5 dark on its own. There is no brand-dark.svg to keep in sync.
  • Use --el-accent-on-surface, not --el-accent. The two are the same colour in light and diverge in dark — --el-accent is the darker FILL, built to carry white ink, and it loses 0.8 of a ratio point as a glyph. This is the row marked above.
  • Never --el-text-inverted. It is var(--color-background): white in light, #0f0f0f in dark. It is the ink FOR a filled field, so a mark painted with it disappears on the page background in light mode — the exact flip the card warns about. On a filled tile, the correct ink is --el-accent-text.

Panel 5 — Favicon and app-icon set

app/favicon.ico (16 + 32, the only icon that ships today) stays as the legacy fallback. Everything else below is new. Sizes are drawn at their true pixel size.

corner radius
icon.svg rx = 32 × 0.22 = 7; apple-icon rx = 180 × 0.22 = 40. 0.22 is --radius-lg (12) over a 56 px tile — the app's own container ratio, so the icon reads as the same family as the UI. The maskable pair has rx = 0.
safe zone
Maskable: the glyph sits inside the centred circle of diameter 0.8 × canvas. A rhombus makes this cheap — its extreme points lie on the axes, not at bounding-box corners, so its circumradius is only 10.3/24 = 0.429 × the glyph box, or 0.57 × canvas across at the 66% render used here. Comfortably inside 0.8. (A square or a letterform pays √2 for the same extent and has to be shrunk to fit.) Non-maskable: the same 66%, centred.
manifest
app/manifest.ts declares both maskable entries with purpose: 'maskable' plus name: 'Motir', short_name: 'Motir', theme_color = the light --el-accent literal, background_color = the light --el-page-bg literal. A manifest is static JSON and cannot read a CSS variable, so these two are hex literals whose provenance is recorded here.
the ico is not enough
Next.js only auto-wires files it finds: app/icon.svg, app/apple-icon.png and app/manifest.ts each have to EXIST. None do today — which is why an iOS "Add to Home Screen" currently gets a screenshot of the page.

Panel 8 — Accessible names: decorative vs informative

The same glyph is decorative in one slot and the entire accessible name in the next. The rule is about the CONTAINER, not the mark: if the visible wordmark is beside it, the glyph is decorative; if the glyph stands alone, it carries the name.

Slot Form Markup Accessible name
Shell top bar (7a) mark only, is a link <Link aria-label="Motir — go to dashboard"><svg aria-hidden> informative — the link's label
Auth card (7b) lockup, is a link <svg aria-hidden> + visible "Motir" decorative — the text names the link
ExploreTopBar (7c) lockup, is a link <svg aria-hidden> + visible "Motir" decorative
PublicTopBar (7d) quiet lockup, is a link <svg aria-hidden> + visible "on Motir" decorative
Email (7e) image, not a link <img alt="Motir"> informative — images are often blocked
Favicon / app icon (5) image, OS chrome manifest.name = 'Motir' informative — the manifest name is the label
OG card (6) image, social embed export const alt informative — the only name an embed gets
  • Never both. An aria-label on the link plus a visible wordmark inside it makes a screen reader announce "Motir" twice, or announce the label and silently drop the visible text. Pick one per slot — the table above IS the pick.
  • The wordmark stays live text. It is never baked into the SVG on a DOM surface, so it is selectable, translatable and searchable — and it survives a user's font-size preference. (next/og and email are the two exceptions, and both are raster surfaces.)

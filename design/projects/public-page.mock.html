The Public page room in project settings

Where a project admin edits the tagline, tags and README that motir.co/p/<key> renders — on app.motir.co, as its own settings room at /settings/project/public. The placement was decided on MOTIR-4171 (rungs 1–2) and is drawn here, not re-opened. Consumed by MOTIR-4171.

Built against shipped reality. The rail is the real app/(authed)/_components/SidebarNav.tsx in settings mode; the Members-room cards are the real ProjectMembersSettings.tsx with the project public; the README field is the real components/ui/MarkdownEditor.tsx; the inputs, buttons, chips and the settings card are the shipped primitives — all server-rendered through the repo’s vitest setup and laid out here under Tailwind’s own compiled output. Only the new row, the three retargets and the room’s composition are authored. Measured at b2d7798b2.

Panel A — the entrance: three doors, drawn inside the shipped parents

Each haloed affordance is a door into (or out of) the room. ① the new Public page row in the rail’s Access group, directly under Members & access, gated like every other manage-only row (project:administer — the key publicProjectsService.setPublicOverview’s assertCanManage asserts; no read-only view, per the 2026-08-08 amendment). ② the Members room’s Hero & overview row, whose link now opens the room instead of a page that 404s. ③ the View public page link, retargeted to the public host — and the share field beside it shows the public URL too, because copying app.motir.co/p/… hands a visitor a 404 (a third retarget MOTIR-4171 owes; see the notes).

Panel B — the room, inside the settings shell

The settings rail with Public page active, and the page in the shell’s content column (max-w-[42rem], the Members room’s width). One settings card carries the three fields and the shipped save bar: the tagline as an Input with its cap as the helper, the tags as removable chips plus a two-state Add tag control with a running count, and the README as the shipped MarkdownEditor — which is WYSIWYG, so the editor is the preview and no write/preview toggle is drawn. The header’s View public page opens the live page on motir.co while the project is public. The save bar is the AI-planning page’s footer grammar: a hint on the left, Cancel, Save changes.

Panel C — states

Six states of the same room, content column only. The README area is shortened on this board (the shipped editor keeps its min-h-[22rem]). The three per-field errors are the three the service throws — ProjectTaglineTooLongError, ProjectTagsInvalidError, ProjectOverviewTooLongError — each shown at its field, with the footer hint the AI-planning page already uses for an invalid form. A failed save that is none of those (a network error, a 5xx) is the shipped toast: “Couldn’t save the public page. Try again.” — edits kept. Not drawn, and absent by design: a non-admin (no row, no room, no read-only view) and a self-hosted build (MOTIR_CLOUD unset ⇒ no public projects ⇒ neither the row nor the route exists).

Panel D — from motir.co: what a manager arriving from the public page does

The answer MOTIR-4171’s criteria ask for, in three moments. The public page shows no edit affordance to anyone (public-surface-hosts.md AMENDMENT 4 row 7 — a cross-origin page cannot know who is looking, and a long-form authoring act belongs where the author already signs in). The manager signs in to the application, picks the project, and opens Settings › Public page. Moments 1 and 2 are schematic — their surfaces are designed elsewhere and are not this asset’s to redraw.

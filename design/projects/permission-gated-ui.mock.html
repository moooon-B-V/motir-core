The failure this panel exists to prevent: a group heading rendered above zero rows. It is what a naive filter produces, and it reads as a loading failure rather than as policy. The rail renders a heading only for a group that has at least one visible entry — the rule the shipped groupSettingsNav() already applies (.filter((section) => section.entries.length > 0)), drawn here so the gating card keeps it.
The dashed block is annotation, not chrome. In the product the surviving group sits directly under the rail head, with no gap and no placeholder. Treatment-table row 1 (HIDE the settings rail entry).
Which entries survive for which role is NOT drawn here — deliberately. The permission key each destination gates on is MOTIR-2468's to name, against that surface's own server guard. What this panel fixes is the SHAPE of a partly-filtered rail, which is the same for any key map.

The shipped component, unchanged: components/projects/NoAccessState.tsx — the EmptyState family with a lock glyph, a serif title, a muted description and ONE action. Not a new screen; the shipped /settings/project/automation page already renders exactly this shape for a non-admin, and this asset extends that precedent to every destination the story hides. Treatment-table row 3 (GUARD — hiding is presentation and never enforcement).
The copy is per destination, not one apology reused eleven times, and the back action goes to the nearest settings page the actor CAN see — Details when they hold anything at all in the area, and Back to projects → /dashboard when the whole area filtered away (panel 1's actor), because a back button that lands on another refusal is worse than no back button. The full title / description / back-label / back-href table is in the design notes.

What this panel decides — and it is only about SHAPE: a removed row leaves no placeholder and no disabled stand-in; the rows below move up. The primary section keeps its single separator from the footer even when the footer has nothing in it, because the separator belongs to the section boundary, not to the rows — a viewer whose settings door is also gone sees the nav simply end, never a hairline floating under nothing. And the primary section can never render empty: Dashboard, Work items, Boards, Roadmap, Backlog and Reports are reads that survive for any actor who can browse the project at all — an actor who cannot browse never reaches this shell, they get panel 3's state on the project itself.
WHICH rows leave is NOT decided here. The three drawn as closing up are illustrative. MOTIR-2471 names the permission each destination needs, read off that destination's own server guard — an entry stays unless its page refuses the actor outright, and a row that merely renders fewer actions is a page-level concern, not a nav one. Treatment-table row 4 (HIDE the project-nav entry).

A DISCREPANCY the run recorded — a fourth row in the findings strip

A run that finds its plan wrong only about the HOW builds the work item through and records what it built differently. The record is a comment on the work item and a pointer on the run; the strip shows the pointer and one label — a count, never a point’s text. It is a RECORD, not a defect and not an ask: the run delivered, and nothing waits on the reader.

Every panel is drawn light and dark. The strip’s existing rows are run-modal.mock.html panel 9’s, verbatim; only the row marked Built differently is new.

D1One discrepancy, one point — alone in the strip.

A build-through that filed nothing else still grows the strip — the strip is absent only when the run produced no finding at all (panel 9 of run-modal.mock.html, not redrawn). The row is a RECORD: the run delivered, nothing waits on the reader, so there is no accent rule and no waiting language. The dot is --el-info.

The row names the leg’s work item (mono, like the bug row) and the number of points — only the count. The points’ text lives in the comment the door opens.

D7The leg’s node on the canvas — nothing is drawn, and why.

No node count ships. Panel 9 of run-modal.mock.html drew a small count on the canvas node as “an index into the strip”, but the shipped node (WorkItemNode’s RunLegBadge) carries a tone and a label only — there is no finding count on a node today, for bugs or plans. This pass therefore draws nothing on the node and adds no count: when the node count ships, a discrepancy is one more finding in it (the default stated in the notes), and that is for the count's own build work item to decide, not this one.

The RUN SECTION on a work item

MOTIR-1789 · MOTIR-1795. A person who dispatches one card wants to know one thing: is it working, and where did it end up. Today Motir answers with a status pill that says In Progress while the account of what actually happened scrolls past in a terminal on one machine and disappears when the window closes. This section is that account, on the card.

It COMPOSES the shipped page. The section is ContentSectionCard’s header grammar over the shipped Card and Pill, in the LATE STACK of app/(authed)/items/[key]/page.tsx. Nothing here is a new primitive, a new colour or a new radius.

It does NOT redraw the pull request. The card’s pull requests and their CI state are the Development section’s, one card up the same stack, drawn at design/work-items/delivery-set.mock.html. The run section shows the RUN; the delivery section shows the DELIVERY. Panel 11 draws them adjacent.

Every state is drawn, and two of them are the reason the list matters. Re-planned is neither a success nor a failure and will be drawn as one of them if nobody draws it. Reporting-offline is a state only a BYOK run can be in — the work happened, the machine simply could not say so — and it exists precisely because the reporter is allowed to fail without breaking the run.

0PLACEMENT — the late stack, after Development, filling with the ONE settle.

The item page’s tier table (design/work-items/design-notes.md § The item page at ARRIVAL) allocates five late regions; this is the sixth, and it goes directly after Development. Adjacency is the argument: Development answers did it ship and this answers what happened while it was being made, and a reader who has just read one wants the other without scrolling past Acceptance to find it. It arrives with the late stack’s ONE settle, not on its own. The page settles TWICE — once when the first content replaces the frame, once when the late stack fills — and a sixth independent boundary would make it settle three times for a region that sits below the fold at arrival. Its pending face is the late stack’s own card chrome plus row-shaped pulse bars, exactly as Development’s is.

1RUNNING — the live timeline.

One row per CARD-SCOPED event the decision closes, in seq order — never by timestamp, because two events written in the same millisecond have no order at all under a clock. Rows that have not happened are drawn as EMPTY rings rather than omitted, so the timeline does not resize as it fills. The “4 of 11” line is the single most useful sentence on this card: it is how a person learns their card was swept up by a story run, and it exists because a run covers a SET.

5CANCELLED and TIMED OUT — two ends that are not failures.

Cancelled is Ctrl-C: a decision, not a fault, so it takes the neutral --el-muted tone. Timed out is the one state no client ever reports — a process that died cannot say so — and it is written by the server’s reap. It takes the warning tone rather than the danger one: the run is not known to have failed, it is known to have stopped saying anything.

6REPORTING-OFFLINE — the run happened; the record did not.

The state most likely to be improvised if it is undrawn, and the one a hosted run can never be in. Reporting is best-effort by design: a 500, an expired token or a dead network must never break a run, so the CLI prints one line and carries on. What reaches Motir is a run that opened and then went quiet. It must not read as a failed run — the work may have shipped perfectly — so the pill is neutral-warning, the notice says which of the two facts is unknown, and the timeline keeps the rows it did receive rather than showing an empty card.

7STREAM-RECONNECTING — a transport state, not a run state.

The browser’s connection dropped, not the run. So the notice sits ABOVE the timeline and the pill keeps saying Running: changing the run’s own tone here would tell a reader something about their agent that is not true. When the stream resumes it replays from the last seq the page holds, so no row is duplicated and none is missed — which is why the copy can promise “nothing will be missed”.

8EMPTY — “nothing has run”, and it must not read as an error.

No red, no warning tone, no “no data” framing. The copy button is the same one /ready already ships.

9RECENT RUNS — designed for twenty, not three.

A card worked by motir auto every night accumulates a run per night for as long as the project lives, so the list is cursor-paged and capped at five with an explicit “Show more”. Newest first, which is load-bearing rather than a default: the item page reads the CURRENT run off the first row, which is why there is no separate “current run” read to keep in step. Each row is agent · disposition · duration · when, and a run that covered a set says so in the same line rather than in a second column.

12THE TONE VOCABULARY — defined once, reused by every run surface.

One row per status. Every tone is a tinted background carrying --el-text-strong — the AA-safe pairing the token rules require — with the hue in a 7px dot rather than in the ink. Nothing signals a run state with a dashed or dotted border, and nothing invents a hue: each dot is an existing --el-* token. The run VIEW — MOTIR-3893's design, which lands in this folder — consumes this table rather than defining a second one.

Status Pill Background Dot Why this tone
queued Queued --el-muted --el-status-todo Owned, not started. Neutral because nothing has happened yet.
running Running --el-tint-sky --el-status-in-progress The product’s existing In-Progress hue, so a run in flight reads like work in flight.
integrated Integrated --el-tint-mint --el-status-done On a session branch. Success tone; the delivery section says whether it merged.
implemented Implemented --el-tint-mint --el-status-done Its own pull request is open. Shares integrated’s tone: both mean the agent finished.
failed Failed --el-tint-rose --el-danger The only danger tone in the set. Reserve it: everything else here is a legitimate ending.
re-planned Re-planned --el-tint-lavender --el-status-planning The Planning hue. Neither green nor red, which is the whole point of the row.
skipped Skipped --el-muted --el-text-tertiary A decision the run made. Always shown WITH its reason; a bare “skipped” says nothing.
cancelled Cancelled --el-muted --el-status-cancelled Somebody pressed Ctrl-C. A decision, not a fault.
timed out Timed out --el-tint-peach --el-warning Written by the server’s reap, never by a client. Warning, not danger: unknown ≠ failed.
reporting-offline Reporting offline --el-tint-peach --el-text-tertiary The RECORD is incomplete, not the run. Warning ground, neutral dot — deliberately not danger.

Ten statuses, five backgrounds. The collisions are deliberate: integrated/implemented are one outcome to a reader, and queued/skipped/cancelled are all “nothing ran”, told apart by their dot and their label rather than by a sixth tint nobody could name.

The /ready RUN STRIP

MOTIR-1789 · MOTIR-1795. /ready is the dispatch surface — it is where a person watching a run chew through a queue actually looks. A row whose item is being worked gains an inline indicator and its current step, linking through to the run.

It is a STATE on an existing row, not a new page, and that constraint is the design. design/ready/ready.mock.html already draws the row and ReadyList.tsx VIRTUALIZES it at a 44px estimate, so the strip lives inside the row’s existing rhythm and costs it no height. Nothing here re-specifies the page, its header, its empty state or its copy button.

The tone vocabulary is not defined here. It is design/runs/run-section.mock.html panel 12, defined once for the whole area; this surface consumes three of its ten rows.

1THE DIFF — one row, both states, adjacent.

The shipped row above, the same row with a live run below. The strip sits immediately after the title and before the meta cluster: the title is the flexible cell, so a strip placed after it shrinks the title rather than pushing the priority, the assignee and the copy button around — and those three are the row’s stable right edge, which the E2E selectors and the reader’s eye both depend on. It is an anchor, not a badge: the whole point of seeing it is to follow it.

2IT COSTS THE ROW NO HEIGHT — measured, not asserted.

The row is 12px padding over its tallest child. Today that child is the 22px avatar (the priority Pill is 20px, the type icon 18px), so the row is 46px and ReadyList.tsx’s 44px estimate is one row-gap out and absorbed by the window’s own tolerance. The strip is drawn at 22px — the avatar’s height, deliberately — so it joins the row without becoming its tallest child. A 24px strip would add 2px to every virtualized row and re-open a measurement that has already survived several rounds of selectors.

3AT LIST SCALE — one row moves, the rest do not.

This is what the strip is FOR: a scoped run has claimed eleven cards and every one of them reads In Progress, so the status column can no longer say which is being worked. The strip is the only thing on the page that can. Rows the run owns but has not reached carry the QUEUED tone — muted, not blue — so the eye lands on the one that is moving. 4THE THREE TONES THIS SURFACE USES — and the one it must not get wrong.

A ready row only ever shows a run that is still OPEN, so seven of the area’s ten tones cannot appear here: a finished run’s card has left the ready set. That leaves three — and reporting-offline is the one that matters. A row whose run went quiet must not look like a failure, because the agent may be working perfectly on a machine that simply cannot reach Motir. It takes the warning ground with a NEUTRAL dot, and the label says what is unknown rather than what went wrong.

5NARROW — the strip is the first thing that drops its detail, and the last that disappears.

At 390px the row already sheds the assignee’s NAME and the copy button. The strip keeps its dot and its step and drops the “4 of 11” — the run’s identity is still reachable by tapping it, and the step is the half that changes. It is the LAST element to disappear, not the first: on a phone, which card is being worked is most of what the page is for.

6WHAT IT IS NOT — three refusals, written down.

Not a progress bar. A run has no percentage: the set is known but a card’s duration is not, and a bar that fills at a guessed rate is a lie a reader will time.
Not a second status. The row already has one, and the card’s workflow status is the board’s. The strip says what a RUN is doing, which is a different question with a different owner.
Not a live log. The step is one phrase from the run’s own event vocabulary. Anything longer belongs on the run view or in the card’s run section, both of which the strip links to.

Pages — the section and its index

MOTIR-7271 for Story MOTIR-5752. A project’s pages get their own primary row in the rail and their own index. They will share the project’s folder system with work items (MOTIR-5753), but this story shows them in neither the /items tree nor its toolbar.

1THE ACCESS PATH — a Pages row in the rail, directly under Work Items.

Position: directly after Work Items. Work Items are the work; Pages are what is written about it. The two are the only surfaces that will share the project’s folder system (the tree is MOTIR-5753’s), so they sit together, and Pages lands above the run surfaces (Ready, Runs, My agents) rather than among them. It is a primary row because every top-level project view is one — the convention SidebarNav.tsx records row by row.

Glyph: NotebookText. Unused anywhere in the app. FileText, the obvious choice, is already the content work-item TYPE glyph (lib/issues/workItemTypeMeta.ts) and the plan-page destination tag; once pages and work items share one tree, a page row with the content-type glyph would read as a content work item. The rail’s own glyphs are all taken by peers (House, CircleDot, CirclePlay, Waypoints, SquareTerminal, Columns3, Map, Sparkles, LayoutList, LayoutDashboard, Inbox, BarChart3, Stamp, Code; History for Resume onboarding), and BookOpen is the Help menu’s Docs.

Registered, not only rendered. PROJECT_NAV_ACCESS gains { href: '/pages', requires: 'page:view' }; without the row canOfferNavDestination answers false and the row silently disappears. A reader without page:view gets no row and the rows below close up — no disabled row, no gap (third rail). The ⌘K Go-to list reads the same map, so it offers Pages under the same rule.

2THE INDEX, populated — a member (holds page:edit).

The heading, the subtitle and New page in the header, where every authed page puts its primary action. The project’s pages, newest edit first, as a flat list — the tree, sub-pages and folders are MOTIR-5753’s. Each row is ONE link to the page: the NotebookText glyph, the title (or Untitled, in italic secondary ink, so a blank page is still a findable row), and Edited <relative time> by <name> — “by you” when the last editor is the reader. A long title truncates on one line; the full title is the page’s own heading.

The third row is drawn hovered (--el-surface-soft). Below the list: what New page looks like while its POST is in flight. It creates an empty page at the project root and moves to it; there is no dialog and no title prompt, because the title is the first thing the page itself asks for (panel 6 of page.mock.html).

3THE INDEX, empty — the member variant and the viewer variant.

The shipped EmptyState. For a member, New page is the call to action and the header keeps its own New page — two doors to one action is what every empty authed index does. For a viewer (no page:edit) there is no action anywhere and the description says who writes pages, so an empty room does not read as a broken one.

5THE INDEX loading — an in-page frame while the list resolves.

PageSkeleton with a REAL header: the heading and subtitle are static strings and New page depends only on the permission the gate has already read, so they paint from above the boundary and are not drawn as bars. The body is five row-shaped blocks (glyph, title, meta) inside the same Card frame, so the list settles in place with no vertical shift. It is an in-page <Suspense> placed after the gate, never a loading.tsx (design/shell/design-notes.md § The navigation-pending grammar). Announced once as “Loading page”; the blocks are aria-hidden.

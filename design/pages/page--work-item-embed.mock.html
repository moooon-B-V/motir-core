Pages — an embedded work-item card

A work item as a block in a page: key, title, type, status and assignee, read live per reader, opening the work item on click. Thirteen panels; light and dark on each state, zh on panel 13.

1The card in a page among prose — edit resting and read resting

A block in the prose column with the rhythm of an image or a table: no float, no shadow. Meta line first (type glyph, mono key, status pill, assignee), the title under it. Edit and read are the same frame; only read is a link. “Just inserted” is drawn from the picked row and is identical to resting, so no card flashes “Unassigned” between the pick and the reload.

3The card’s block states — edit hover, edit selected, read hover

The edit card is not a link: a link that follows a click in an editable document fights the caret, so the cluster’s Open button is the door. The read card is ONE link whose name is its own content (key, title, type gloss, status word, assignee) and has no interactive descendant, so a link can never nest in a link.

4Unavailable, in edit and in read — and the archived card beside it

The unavailable card shows no key, no title, no type, no status and no assignee. A deleted item, an item the reader may not browse (accessible: false) and an id with no entry at all draw the same card, so a reader cannot tell hidden from deleted — the rule WorkItemChipView already records: “Deleted, or not readable by this reader — drawn the same, on purpose, with neither key nor title”. An item of another project the reader can browse renders live, as the chip does. An archived item the reader can see keeps all five facts in a muted frame with a neutral Archived pill, and still links.

7The picker with the insert-as band — mention mode and card mode

@ opens it in mention mode (the shipped default, unchanged); the toolbar control opens it in card mode. The band at the foot switches modes by mousedown on a segment or by Tab while the picker is open — focus never leaves the editor, or the suggestion’s range is lost. Enter on a row calls the shipped onPick in mention mode and the host’s embed.pick in card mode. The rows and the picker’s error, empty and loading states are the shipped ones, drawn as context and not specified here.

9Chip → card — from the chip’s affordance to the card that replaces it

The chip renders through the host, so the control sits in the package wrapper beside it and never inside it. The conversion is one transaction (not a delete plus an insert): the selection lands on the new node and one undo returns the previous form. These chip states are drawn here because the chip has no design asset of record in the repository (open questions).

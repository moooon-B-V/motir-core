1THE ACCESS PATH AND THE POPULATED TREE — Pages in the rail opens /pages, now a tree; a page row opens /pages/{id}.

Door: the shipped Pages rail row (active on the whole /pages subtree, design/pages/pages.mock.html panel 1) opens this tree. A page row’s title is a link to /pages/{id} (the sidebar mock is where it lands); a folder row’s whole row toggles it, as in /items.

Order: each level shows its folders first, then its pages, each kind in position order — ADR docs/decisions/pages.md §4 as amended by AMENDMENT 1; the level read is MOTIR-7370’s listTreeLevel. A page title is the writer’s and is never translated — the zh board shows English titles beside zh chrome.

The subtitle loses “most recently edited first” — the tree is in position order. Token refresh is drawn hovered: --el-surface fill and, for an editor, the drag handle in the left gutter (panel 11).

7AT SCALE — a level of 50 rows ends in Load more.

A level is read 50 at a time (PAGE_LEVEL_PAGE_SIZE, ADR §4), folders then pages under ONE keyset cursor (MOTIR-7370). When a level has more, its last row is Load more, which appends the next 50 in place. A keyset cursor knows no total, so the count says how many are shown, not “of N” as /items’ offset paging does. Long levels are windowed with TreeTable’s windowing.

11DRAG — in progress, a valid target (before / after / inside), a refused target, and a refused drop.

Handle: a GripVertical in the row’s left gutter, shown on hover and focus for an editor only; the whole page row is the dnd-kit draggable (MOTIR-7376). Folder rows are drop targets and never draggable — a folder moves with Move to…, as in /items. Bands: on a PAGE row the top quarter means BEFORE, the bottom quarter AFTER, the middle half INSIDE; a FOLDER row is INSIDE only. Before / after is drawn as the accent line at the target’s indent; inside as the tint and ring. Hovering a collapsed row for 600ms expands it. Dropping on the root target moves the page to the project root, after the root’s pages.

Refusals: a page over itself or anything inside it is refused before the drop (MOTIR-7376’s pre-check) and shown as drawn; the depth and cross-project refusals only the server knows, so those snap back with a toast. Every commit goes through usePageMove (MOTIR-7374). No keyboard drag: Move up / Move down / Move to… are the keyboard path, so the handle is aria-hidden and out of the tab order.

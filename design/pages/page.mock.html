8THE SAVE INDICATOR — saved, saving, offline.

Where: the trailing end of the toolbar, which is sticky, so the indicator is in view wherever the writer is in a long page and sits where their eyes already are. It is a polite live region (role="status"), so a screen reader hears the change without losing its place. Title edits report through the same indicator.

Saved — nothing is waiting; a quiet check in secondary ink. Saving… — a batch of edits is in flight: the editor sends after 1 s of quiet, or every 5 s while typing continues, one request at a time (MOTIR-7275). Offline — edits kept — the last save failed for lack of network; the edits stay buffered in the tab and are resent with backoff (2 s doubling to 30 s) and on the browser’s online event, and the next success reads Saved. It is the only value with a fill (the warning tint), because it is the only one that asks something of the writer: its tooltip says to keep the tab open.

9REFUSED AS TOO LARGE — PAGE_BODY_TOO_LARGE (413).

The save route answers 413 { code: 'PAGE_BODY_TOO_LARGE', limit, size } when the merged body would pass 2 MiB (PAGE_BODY_MAX_BYTES) or one request passes 1 MiB (PAGE_SAVE_MAX_BYTES); nothing is written either way (lib/pages/routeErrors.ts). The editor then reports too_large and STOPS sending (MOTIR-7275), so the indicator reads Not saved in danger ink and a callout opens under the toolbar. It says what happened (the edits since the last save are not saved, and nothing more will be), and what to do: copy out what to keep and reload to the last saved version; make room by moving sections to a new page. The content stays in the editor so it can be selected and copied.

Both actions are secondary buttons — neither is the obvious next step for every writer, and Reload discards the unsaved edits, which the body says before the button does. New page in a new tab opens the new page beside this one, so the writer can paste a section across without losing this tab’s unsaved text.

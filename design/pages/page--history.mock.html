MOTIR-7381 for Story MOTIR-5754. A DELTA on design/pages/page.mock.html (MOTIR-7271), composed with MOTIR-7367’s approved sidebar-tree delta (page--tree-sidebar.mock.html), whose sidebar tree and breadcrumb are drawn here only as context. Page content is the writer’s and is never translated. Spec, copy and keys: design-notes.md § History.

1CLOSED — the page with the History control in its title row

History sits at the trailing end of the TITLE ROW: the breadcrumb MOTIR-7367 drew stays above, the title keeps the row’s leading edge, and the control is a Button variant="secondary" size="sm" with the lucide History glyph and a visible label. It is in the title row and not in the toolbar because the toolbar is a writer’s and History is every reader’s: a viewer, who gets no toolbar, gets the same control in the same place (panel 14). aria-expanded / aria-controls="page-history".

The page tree sidebar, the breadcrumb, the toolbar and the editor are MOTIR-7367’s and MOTIR-7271’s, unchanged — the toolbar is a placeholder strip here.

4POPULATED — several authors and a restore row; the panel beside the page

A right-hand side panel BESIDE the page (Notion’s layout), 340px, --el-page-bg with a left rule in --el-border. It pushes the reading column rather than covering it, so the page stays readable while the list is open. Rows are newest first. A row: avatar 24px · v{n} · Current chip on the newest · time at the trailing end (relative under 24 hours, absolute after) · author name below · Restored from v{n} on a restore row.

Composition with the page tree: at ≥ 1440px the rail, the tree sidebar, the page and the panel sit side by side (this board). Between 1280 and 1439px the tree sidebar hides while History is open and comes back when it closes — the reader’s stored hide/show preference is not written. Below 1280px (where the tree is already hidden) History opens as an overlay sheet from the right over --el-overlay-scrim with --shadow-modal (the narrow board). Closes by the close button, Esc, pressing History again, the scrim (narrow only), or navigating to another page.

7A VERSION SHOWN — before and after, beside the current page

Pressing a row (not Current) opens compare: the main column splits into the current page (left, where it already was) and the selected version (right, next to the panel), both rendered read-only by the same .motir-prose rules. No character diff — two documents side by side. The version column sits on --el-surface-soft so it never reads as the page. The tree sidebar hides while compare is open (the breadcrumb’s Show page tree stays), and comes back when it closes.

The version column’s head: v3 · author · time · Restore this version (editors only) · close (×). The current column’s head carries the writer’s save indicator, because a save can still be in flight (panel 13). Esc, the ×, or pressing the selected row again closes compare and returns to the editor. A viewer sees no Restore (second board).

13UNSAVED EDITS — Restore held until the page says Saved

While the writer’s save indicator is anything but Saved (Saving…, Offline — edits kept, Not saved), Restore is disabled and a line under the version’s head says why and when it comes back: a restore applied over a pending save would race it. It enables itself the moment the indicator reads Saved. (Not saved — the too-large stop — never returns to Saved without a reload, so Restore stays held there; the base design’s callout already tells the writer to reload.)

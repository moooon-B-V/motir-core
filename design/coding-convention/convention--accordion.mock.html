Decision: keep the draft, never block, never ask. The editor stays mounted in state with its text; the collapsed header gains the peach Unsaved draft marker (part of the button’s accessible name, so a screen reader hears it). Expanding that card again returns straight into Edit with the text and the cursor position intact. A collapse never drops text. Only Cancel discards a draft, and a successful Save clears it. Several drafts may coexist (one per repository); each is marked. Leaving the page (reload, navigation, closing the tab) with any draft present raises the browser’s unsaved-changes prompt. A confirm dialog was rejected as friction on a non-destructive action, and blocking was rejected because it traps the person in a 20 KB editor while they look up another repository.
Panel 6 — Narrow viewport (360px): the header row wraps; nothing is truncated

The chevron and repository stay on the first line, the state pill and byline wrap beneath. A long name such as nextjs-prisma-vercel-starter breaks at the slash-free word boundary rather than ellipsising, because the name is the thing that tells repositories apart.
Panel 7 — Keyboard and screen-reader behaviour
Concern Behaviour
Structure Each card is a heading (h3) containing one <button>; the body is a role="region" labelled by that button (aria-labelledby), and the button carries aria-controls pointing at it.
aria-expanded true on the one open header, false on every other; it flips in the same update that collapses the previous card.
Keys Enter and Space activate the focused header. Tab moves through the headers and, inside the open card, through Edit and the editor controls. No arrow-key roving is added: seven headers is a short tab path and the page already has other tab stops.
Focus Focus stays on the header that was activated — on expand, on collapse, and when a sibling collapses as a result. It never moves into the body and never jumps to the newly open card. Re-expanding a card with a draft returns focus nowhere new; the person tabs into the editor.
Accessible name The button’s name reads, in order: repository owner/name, version and state, byline, then markers — “motir-co/motir-core, v7 edited, Edited by Zhu Yue Oct 21 2026, Newer derived waiting, Unsaved draft”.
Announcements No live region. The expanded state change is announced by the button itself; a collapsed draft is announced by its marker in the name.
Contrast Every ink is --el-text-strong or --el-text-secondary; markers put the hue in the tint background. No --el-text-muted, --el-text-faint or --el-danger-text.
